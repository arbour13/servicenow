# Widget Studio — Comprehensive Review (2026-07-21)

Scope: functionality, usability, accessibility, code quality, and robustness. Every finding was
verified by reproducing it live (real hit-tested clicks and dispatched events against the running
app), plus targeted source reads. The console stayed completely clean — zero errors or warnings —
through the entire walkthrough, including a corrupted-localStorage cold start.

Re-checked same day after other-agent activity elsewhere in the tree: `widget-studio.html`
unchanged since 10:47:31 (its last pre-review edit), so all line references below are current.

No Critical (crash / unrecoverable corruption) findings; the top tier is Major.

## Major — wrong behavior / silent data loss

### 1. ~~Unsaved work is silently destroyed by browser refresh/close~~ — FIXED 2026-07-22
A `beforeunload` handler now warns when `_dirty` (added in `componentDidMount`, removed in
`componentWillUnmount`). Verified live: clean state → refresh unblocked; after an edit → browser
warns. In-app discards still route through `requestDiscard` as before. (Draft auto-persist remains
a possible future enhancement, but the silent-loss gap is closed.)

### 2. ~~`esc()` doesn't escape double-quotes → malformed exported template~~ — FIXED 2026-07-22
`esc()` now escapes `"` as `&quot;`. Verified live end-to-end: `title` = `Say "hi"` serializes as
`title="Say &quot;hi&quot;"`.

### 3. ~~Z-index exports invalid CSS (`z-index: 5px`)~~ — FIXED 2026-07-22
The px-append in `numField` is now gated on a `UNITLESS_KEYS` exclusion set (`zIndex`, `opacity`,
`fontWeight`, `lineHeight`, `flexGrow`, `flexShrink`, `order`) rather than the review's suggested
SIZEKEYS whitelist — numField's other live keys (`min/max-Width/Height`) are *not* in SIZEKEYS and
must keep their px-append. Verified live: z-index `5` stores as `5`; minWidth `200` still → `200px`.
The dead Position copy at 4808 (`rawField`) is unchanged.

### 4. Free-text style fields accept anything, silently
Typing `abc` into Height writes `height: abc` into the class and it flows straight into the
exported SCSS. No validation, no error styling, no revert. Applies to every `numField`/`rawField`.

## Usability

### 5. First-run is a dead end for discoverability
Palette chips respond only to drag (mousedown+move, `startAdd` 631); clicking a chip does nothing,
with no feedback. The empty root canvas shows no "drag an element here" prompt — the "+ Add
element" empty-state exists only for grid columns, flex containers, and composables (2610-2640).
Click-to-add is #1 in the existing backlog; this review re-confirms the priority.

### 6. Shell breaks below ~1100px viewport
At 900px the right inspector is clipped off-screen (swatches, corner picker, "STYLED" chip cut),
the code-drawer tabs overlap into two colliding rows, and Save/Open/Export scroll out of the
header, with a horizontal scrollbar on the whole page. Panels are user-resizable, but there's no
responsive floor or auto-shrink.

### 7. Corrupt widget library = silent apparent data loss
If `widgetStudio_widgets` fails to parse, `listWidgets()` returns `[]` (248) — the library shows
"No saved widgets yet", and the next Save overwrites the blob permanently. Graceful no-crash is
good; silent discard of potentially recoverable data is not.

### 8. Picker target state leaks across elements
`_bwSide`/`_radCorner` are flat instance props; selecting a different element keeps the previous
element's "Editing Left" target (verified live), while `select()` resets only `_estate` (1019).
Defensible either way, but inconsistent with how state-layer selection resets.

### 9. Small inconsistencies
Placeholder casing varies: Size uses `auto`, Position insets use `Auto`, min/max uses `—`. The
"list" chip creates an empty `<ul>` (no starter `<li>`), and li's have no default text, so exports
contain empty `<li></li>` pairs and a freshly built canvas can look completely blank while holding
11 elements.

## Accessibility

### 10. Keyboard coverage is systemically partial: 115 of 236 clickable controls unreachable
The foundation is genuinely good — an `a11y()` helper (1831), global focus-ring CSS (49-52),
proper roles on segs/tiles/switches/tabs, and a real shortcut set (⌘S/⌘Z/⌘D/⌘C/⌘V/⌘G/Delete/Esc).
But whole control families skipped it: border side zones and corner handles (3465-3475), border
style swatches (4994), Size Auto/Full/Fit presets, the I/U/S and AG/ag/Ag typography tiles, Layers
tree rows (2062), canvas nodes, "+ Add class", and the class-chip ×. Since the palette is
drag-only, a keyboard user cannot add or reorder elements at all.

### 11. Ambiguous duplicate labels
Justify and Align rows both expose tiles labeled just "Start/Center/End" with no
`role="group"`/`aria-label` on the rows (verified in DOM). `seg()` supports a group label (1882);
the icon rows don't use one.

### 12. Tooltips are mouse-only
`tt()` binds `onMouseEnter/Leave` only (1854) — keyboard focus never shows a tooltip, so sighted
keyboard users lose all the icon-control hints.

## Code health

### 13. Dead code
`advancedLayout` (4800) is never called, and `offsetGrid` (3992) is referenced only by it —
including a second, divergent Z-index implementation. Left over from the "Position moves into
Structure" refactor.

### 14. Brace style
347 single-line brace-less `if` statements, against the stated always-curly-braces preference. It
is the file's own consistent idiom, so this is a policy call, not drift within the file.

### 15. What's healthy
The generators are solid — `kebab()` correctly produces `-webkit-line-clamp`, colors hoist to
`$widget-* !default` theme tokens, `var(--box-shadow-md)` maps to `$box-shadow-md !default`,
states nest as `&:hover`/`&::before`, and `clearKeys` prevents shorthand/longhand ambiguity. Undo
history is capped (120 entries) and coalesced (600ms). No `console.log`s, no TODOs. Monaco CDN
load has a failure fallback flag.
