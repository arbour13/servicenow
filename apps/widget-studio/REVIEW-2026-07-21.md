## Major — wrong behavior / silent data loss

### 1. ~~Unsaved work is silently destroyed by browser refresh/close~~ — FIXED 2026-07-22
Superseded same day by **draft auto-persist**: `rawSave()` (already the mutation choke point)
mirrors the working widget to `widgetStudio_draft` (debounced 400ms), and `load()` restores it —
tree, styles, tokens, code buffers, name/ID, dirty flag, and the open library record. Refresh/crash
is now lossless, so the blocking `beforeunload` dialog was dropped in favor of a silent
flush-the-draft handler (the native dialog can't be styled; the user wants custom modals only).
In-app discards (New/Open) still route through the custom `requestDiscard` modal. Verified live:
build → refresh → exact state back (incl. `_dirty` and Save-button dot); Save/Open/New keep the
draft in sync; corrupt draft blob → clean cold start.

### 2. ~~`esc()` doesn't escape double-quotes → malformed exported template~~ — FIXED 2026-07-22
`esc()` now escapes `"` as `&quot;`. Verified live end-to-end: `title` = `Say "hi"` serializes as
`title="Say &quot;hi&quot;"`.

### 3. ~~Z-index exports invalid CSS (`z-index: 5px`)~~ — FIXED 2026-07-22
The px-append in `numField` is now gated on a `UNITLESS_KEYS` exclusion set (`zIndex`, `opacity`,
`fontWeight`, `lineHeight`, `flexGrow`, `flexShrink`, `order`) rather than the review's suggested
SIZEKEYS whitelist — numField's other live keys (`min/max-Width/Height`) are *not* in SIZEKEYS and
must keep their px-append. Verified live: z-index `5` stores as `5`; minWidth `200` still → `200px`.
The dead Position copy at 4808 (`rawField`) is unchanged.

### 4. ~~Free-text style fields accept anything, silently~~ — FIXED 2026-07-22
`numField`/`rawField` now validate through `CSS.supports()` before writing — an invalid value never
reaches the class styles or the exported SCSS. While a field holds an invalid value the input shows
it in red error styling; leaving the field reverts to the last good value. `%`, `calc()`, and
`var(--…)` all still pass. Verified live: `abc` into Height → red, model untouched; blur → reverts;
`240` → `240px` written.

## Usability

### 5. ~~First-run is a dead end for discoverability~~ — FIXED 2026-07-22
Palette chips now add on click (`clickAdd`): the element lands in the selected container, or the
nearest ancestor that may legally hold it (same `allowsChild` guard as drops); drag still works, and
a completed drag suppresses the trailing click so nothing double-adds. The empty root canvas shows
the same "Click or drag an element from the palette / + Add element" prompt as empty containers.
Verified live: chip click adds + selects; Enter on a focused chip adds too; drag-add unchanged.

### 6. ~~Shell breaks below ~1100px viewport~~ — FIXED 2026-07-22
Panels now auto-shrink to fit: `effPanelWidths()` clamps the rendered left/right panel widths
proportionally toward their minimums (292/340) so both panels plus a 330px canvas fit the viewport;
stored prefs are untouched, so widening the window restores the user's sizes. The horizontal-scroll
fallback only kicks in below the ~972px absolute floor (was up to ~1410px with widened panels).
Below 1150px the header drops its field labels + base-class hint and shrinks the Name/ID inputs so
the device switcher and Save/Open/Export stay on screen. The code-drawer tab pill stays on one row
(pans internally instead of wrapping into the fixed-height bar) and the read-only hint strip
truncates with an ellipsis + title tooltip. Verified live at 1600/1280/1150/1000/900px: shrink at
1150 (371/439 from stored 420/500), minimums + small scroll only at 900, full restore at 1600,
console clean throughout.

### 7. ~~Corrupt widget library = silent apparent data loss~~ — FIXED 2026-07-22
An unparseable blob is now preserved under a datestamped backup key
(`widgetStudio_widgets_corrupt_<date>`) before the empty library is returned, and the library modal
shows a notice naming the backup key. Verified live with a corrupted store.

### 8. ~~Picker target state leaks across elements~~ — FIXED 2026-07-22
`select()` now resets `_bwSide`/`_radCorner` alongside `_estate` when the selection changes.
Verified live.

### 9. ~~Small inconsistencies~~ — FIXED 2026-07-22
Placeholders now use the literal CSS defaults everywhere: Position insets `auto` (was `Auto`),
min-width/height `auto` and max-width/height `none` (was `—`). The "list" chip drops a `<ul>` with
one starter `<li>`, and a new `<li>` carries "List item" text — shown on the canvas (editable in
place) and emitted by the serializer, so exports no longer contain empty `<li></li>` pairs.

## Accessibility

### 10. ~~Keyboard coverage is systemically partial: 115 of 236 clickable controls unreachable~~ — FIXED 2026-07-22
One sweep wired `a11y()` through the skipped families: border side zones + corner handles, border
style swatches, Size Auto/Full/Fit presets, the typography align/I-U-S/case tiles, Layers tree rows
(select + expand/collapse + row action buttons), context-menu rows and the ancestor submenu, the
Add-inside popover (Enter in its search adds the top match; rows are focusable), palette chips
(click-to-add doubles as Enter/Space activation — a keyboard user can now add elements), the
Add-element prompt pill + quick chips, class-chip remove ×, attribute quick-chips/removes, binding
`{ }` buttons + path chips, color swatches + picker buttons + token diamonds/`{}` + token-menu rows,
gradient stop add/remove, the device-breakpoint switcher, the Box-model toggle, library open rows,
and the code-drawer bar. Re-audited live with the same methodology: 3 of ~200 non-canvas clickable
controls remain unreachable (decorative breadcrumb fragments). Canvas nodes deliberately stay
mouse-first — selection, actions, and reorder are all keyboard-reachable through the Layers rows,
their action buttons, and the context menu.

### 11. ~~Ambiguous duplicate labels~~ — FIXED 2026-07-22
`iconRow()` takes a group label and every call site passes one (Display/Direction/Justify/Align/
Wrap/Align self/Sizing); the typography tile rows, size preset rows, position presets, and border
style row got `role="group"` + `aria-label` too. Verified in DOM: 12 labeled groups on a flex
container's inspector.

### 12. ~~Tooltips are mouse-only~~ — FIXED 2026-07-22
`tt()` now also binds `onFocus`/`onBlur` (same delay/positioning), and the handful of controls with
bespoke hover handlers (undo/redo, class-chip ×) call showTip/hideTip from their own focus
handlers. Verified live: focusing the dark-mode toggle shows its tooltip.

## Code health

### 13. ~~Dead code~~ — FIXED 2026-07-22
`advancedLayout` and `offsetGrid` (and the divergent Z-index copy inside them) are deleted.

### 14. Brace style
347 single-line brace-less `if` statements, against the stated always-curly-braces preference. It
is the file's own consistent idiom, so this is a policy call, not drift within the file.

### 15. What's healthy
The generators are solid — `kebab()` correctly produces `-webkit-line-clamp`, colors hoist to
`$widget-* !default` theme tokens, `var(--box-shadow-md)` maps to `$box-shadow-md !default`,
states nest as `&:hover`/`&::before`, and `clearKeys` prevents shorthand/longhand ambiguity. Undo
history is capped (120 entries) and coalesced (600ms). No `console.log`s, no TODOs. Monaco CDN
load has a failure fallback flag.
